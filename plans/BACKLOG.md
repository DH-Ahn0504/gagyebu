## A. 계절 테마 분리 (크기: 큼, 4단계로 나눔)
결정: 달에 따라 **자동 전환**, 분류 색 점 8색은 **테마마다 따로**(`--cat-1`~`--cat-8`).
1단계(색 변수 정리)는 끝났습니다. 남은 단계:
1. `<html data-theme="winter">`를 붙이고, 색 변수만 `[data-theme="winter"]` 블록으로 옮김. 크기·간격·곡선 변수는 `:root`에 둠. `color-scheme`도 테마 블록으로. 서리(`--frost-edge`)·촛불빛(`--lead-glow`)은 값이 비면 안 보이게 해서 다른 계절에서 자동으로 꺼지게 함. (designer, 작음~중간)
2. 눈 효과 분리: `snow.js` 맨 앞에서 `data-theme`이 winter가 아니면 바로 종료, 눈 색은 CSS 변수(`--effect-ink`)에서 읽기. 설정 문구 "눈 내리는 효과"를 "계절 효과"로. (coder, 작음)
3. 분류 색 점: `app.js`의 `catColor`(hsl 계산)를 `--cat-1`~`--cat-8` 변수로 교체. 겨울 8색은 금색(데이터 강조)·빨강(경고/음수)과 헷갈리지 않게 고름. (designer + coder, 작음)
4. 월에 따라 테마 자동 선택(예: 12~2월 winter) + `theme-color` meta 갱신. `charts.js`는 그릴 때마다 CSS 변수를 읽으므로 테마 전환 뒤 다시 그리기만 하면 됨. 봄·여름·가을 색 제작은 그다음이며 **taste-skill 사용 전 사용자 허락 필요**. (coder, 작음~중간)
- **1번 완료 (2026-11-07)**: `<html data-theme="winter">`, `:root`(크기·모양·움직임 17개) + `:root, [data-theme="winter"]`(색 37개 + color-scheme)로 분리. 54개 변수의 이름·값이 작업 전과 같음을 확인. (이후 분류 색 8개와 `--effect-ink-rgb`가 더해져 지금은 46개) `.panel`·`.summary`에는 대체값만 추가(`var(--frost-edge, transparent)`, `var(--lead-glow, 0%)`).
- **봄·여름·가을 블록을 만들 때 지킬 것** (1번 보안 검사 결과):
  1. 겨울 색 변수 46개(+ `color-scheme`)를 **빠짐없이 다시 정의**할 것. 하나라도 빠지면 그 색은 겨울 색으로 남음.
  2. `--frost-edge: transparent; --lead-glow: 0%;`를 **직접 써 줄 것**. 안 쓰면 서리·촛불빛이 다른 계절에도 보임. (`:root`가 항상 html에 맞아서 '자동으로 꺼지지' 않음)
  3. 계절 블록은 **항상 겨울 블록 뒤(파일 아래쪽)**에 둘 것. 둘의 우선순위가 같아서 앞에 두면 겨울이 이김.

## B. 안정성 보완 (크기: 작음 × 3, 효과 높음~중간)
1. **내역 저장 버튼 중복 제출 방지** (높음): 내역 폼·삭제·자동 지출 폼·분류 폼·잔액 폼에 저장 중 잠금 + try/finally + 쉬운 오류 문구. 예산 저장 핸들러(`app.js` 예산 부분)와 같은 방식. 확인: 인터넷을 느리게 해 두고 "추가"를 두 번 눌러 1건만 생기는지.
2. **인터넷 끊김·시작 오류 처리** (중간): 15초 자동 새로고침 실패 시 경고창(alert)이 반복되지 않게 조용히 받고 "연결이 끊겼어요" 띠만 표시. 앱 시작(`S.me()`, `load()`) 실패 시 "다시 시도" 버튼이 있는 안내. 자동 지출 폼의 오류 `alert`는 `.error` 칸으로. 전체 오류 `alert`는 토스트 오류 모양(`#toast.is-error`)으로. (coder + designer)
3. **통장 현재 잔액 저장이 오래된 데이터로 계산되는 문제** (중간): 저장 직전에 `await S.load()`로 최신 내역을 받아 계산하고, 값이 바뀐 통장만 저장. 지금은 4개 통장을 모두 덮어써서 상대방이 방금 고친 값이 사라질 수 있음.

## D. 낮은 문제·정리 (급하지 않음, 거슬릴 때 처리)

- 망가진 금액(NaN/문자열)이 조용히 0으로 처리됨 → `console.warn` 또는 "금액을 읽지 못한 내역 N건" 표시. 망가진 이체가 "받는 통장" 목록에서 빠지는 문제는 `logic.js` 필터에 `t.transfer_account_id === accountId` 조건 추가.

- 분류 삭제 버튼의 `split("|")`: 이름에 `|`가 있으면 잘림 → `indexOf` 또는 `data-type`/`data-name` 분리.

  - 이 저장소는 **공개**임. 비밀키·이메일·실제 금액·내역은 절대 올리지 말 것. `.gitignore`의 위 제외 목록은 빼지 않음.
  - 대신 앱 폴더를 가끔 **다른 곳에 복사해서 백업** (클라우드 드라이브나 USB). 특히 코드를 크게 바꾼 뒤와 `schema.sql`을 바꾼 뒤에 한 번씩.
- 분류 이름의 `catColor` 외 글자 크기·간격 값 정리(직접 쓴 px 10곳 이상, 같은 규칙 중복), 앱 로딩 표시("불러오는 중…"), 비밀번호 찾기 없음.
- 15초마다 목록을 통째로 다시 그려 키보드·스크린리더 위치가 처음으로 돌아감 → 받은 데이터가 이전과 같으면 다시 그리지 않기.
- 설치용 `manifest.webmanifest` 추가(아이콘은 이미 있음). 서비스워커는 옛 코드가 남는 문제가 있어 보류.
- 눈 효과와 `backdrop-filter: blur`가 같이 돌 때 아이폰 성능 → 실제 기기에서 먼저 재 보기. 예산 막대 `width` 애니메이션은 `transform: scaleX`로 바꾸면 더 가벼움.
- 파일 이름에 버전(`app.js?v=날짜`)이 없어 배포 직후 옛 파일과 섞일 수 있음. 외부 글꼴(Google Fonts, jsdelivr)을 앱 폴더에 직접 넣기. 쓰지 않는 Inter 글꼴 내려받기 제거.
- CSP(허용 출처 제한) meta: 잘못 넣으면 로그인·사진이 막힘. 넣은 뒤 실제 휴대폰에서 로그인·사진·차트·글꼴 확인 필수. 화면 코드가 `style=""` 속성을 써서 `style-src`에 `'unsafe-inline'`이 필요.
- `style.css` 25줄 근처 옛 주석("spring 블록으로 덮어씀" 예시만 있음)을 나중에 다듬기 (낮은 우선순위).
- 서버 쪽 점검 항목은 비공개 메모(`supabase/비공개-할일.md`)에 있음.

## E. 기능 아이디어 (효과 대비 만들기 쉬운 순)
(DB 변경이 필요한 건 저축 목표뿐)
1. **상대방 새 내역 표시**: 15초 새로고침 때 새로 생긴 상대방 내역을 "나윤님이 2건 추가" 토스트 + 줄 강조. 토스트는 이미 있음. (coder + designer, 작음~중간)
2. **분류 막대를 누르면 그 분류 내역으로 이동**: `openHistory`가 분류도 받게. `vendor/charts.js`는 건드리지 않고 `app.js`에서 클릭 연결 + 키보드 접근(role/tabindex). (coder, 작음)
3. 입력 창의 **"복사해서 새로"** 버튼. (coder, 작음)
4. **하루 평균 + 이 속도의 월말 지출**. (coder, 작음)
5. **예산 막대에 곧 빠질 자동 지출 연한 구간** (`charts.js`의 `plan`에 committed 기능이 이미 있음). (designer + coder, 작음)
6. 빈 화면 안내 다듬기(예산 없을 때 "예산 정하기" 링크). (designer, 작음)
7. '함께' 통장 지출을 누가 썼는지 비율 (`created_by` 이미 있음). (coder, 작음)
8. 이상 지출 표시(한 건이 그 분류 최근 3달 한 건 평균의 3배 이상). (coder, 중간)
9. 누적 지출 선 그래프(이번 달 vs 지난달). (designer + coder, 중간)
10. 첫 화면 좌우 스와이프로 달 바꾸기. (designer + coder, 중간)
11. **공동 저축 목표** + 원형 진행 표시: `accounts`에 `goal_cents` 칸 추가 필요 → **DB 변경이므로 사용자 확인 후** `alter table accounts add column if not exists goal_cents bigint check (goal_cents > 0);`. (coder + designer, 중간)
- 일부러 뺀 것: 정산(사용자가 필요 없다고 함), 진동(아이폰 사파리 미지원), 밀어서 삭제, 푸시 알림·은행 연동·AI 분류.
- 제안만 하고 아직 없는 것: 검색, 월간 리포트 비교("지난달보다 식비 12%↑"), 영수증 사진 첨부, PIN 잠금.

## 작업 규칙 (이 프로젝트)
- 순서: planner(계획) → designer(디자인)/coder(코드) → security(보안 검사).
- DB를 바꾸는 SQL은 사용자가 Supabase SQL Editor에서 직접 실행. 코드를 올리기 **전에** 실행해야 저장 오류가 안 남.
- 무거운 디자인 스킬(taste-skill, unslop, animate 등)은 사용자 허락 후에만 사용.
- 커밋·인터넷 올리기는 사용자가 말하기 전에는 하지 않음.
- 상태: 계절 테마 분리(11/7~8)와 가을 테마(11/9) 변경은 아직 커밋되지 않았다(`style.css`, `test.js`, `theme.js` 수정됨). 사용자가 말하기 전에는 커밋·올리기를 하지 않는다.
